\subsection*{1. Logistic Regression}

\subsubsection*{(a)}

The analysis of the full dataset was peformed using a logistic regression model:

\[
\log\left(\frac{p}{1-p}\right) = \beta_0 + \beta_1 \cdot hours
\]

The threshold for when the function reaches 0.5 and thus the binary output returns 1 was calculated using the following formula.

$$
0.5 = \frac{1}{1+ e^{-(\beta_0 + \beta_1 x)}} 
$$

$$
{1+ e^{-(\beta_0 + \beta_1 x)}} = 2
$$

$$
e^{-(\beta_0 + \beta_1 x)} = 1
$$

$$
-(\beta_0 + \beta_1 x) = 0
$$

$$
x = - \beta_0 / \beta_1
$$

The results show a clear relationship between study hours and the probability of succes. The model provides a good fit to the data and achives classification performance using the chosen decision threshold.

Final model function that resulted:

\[
\log\left(\frac{p}{1-p}\right) = -10.83988   + 0.2091565  \cdot hours
\]

Final threshold for when the function reaches $0.5$ probability:

\[
51.82663 
\]

\subsubsection*{(d)}

Logistic regression is a simple classification method for binary outcomes.
One of its main advantages is that the estimated coefficients can be interpreted in terms of log-odds and odds ratios, which makes the relationship between predictors and the response variable easier to understand.
Another important advantage is that the model produces predicted probabilities in the range:

\[
0 \leq p \leq 1
\]
making it a valiable method for probabilistic interpretation and decision-making problems. It is also computationally efficient and performs well on relatively small datasets. Lastly, it does not require the predictor variables to follow a normal distribution.

A major limitation of logistic regression is the assumption of a linear relationship between the predictors and the log-odds of the outcome:

\[
\log\left(\frac{p}{1-p}\right) = \beta_0 + \beta_1 x
\]

If the true relationship is non-linear, the model may provide poor predictive performance.
This method can also be sensitive to outliers and influential observations, especially in small datasets although the addition of the point \((115,1)\) caused only a small change in the estimated coefficients and decision boundary.
%Another issue is the possibility of perfect separation, where the classes are completely separable, causing instability in parameter estimation.
Finally, logistic regression may perform worse than more advanced machine learning methods when dealing with complex decision boundaries or large numbers of interacting variables.

\noindent\textbf{Note on $f_2$.} The original model stated in the problem is $f_2(x) = axe^{-bx+c}$. However, this form is not identifiable: the parameters $a$ and $c$ are collinear since $a \cdot e^{c}$ constitutes a single constant. 
The model is therefore reparametrised as $f_2(x) = Axe^{-bx}$, where $A = a\,e^{c}$, which is mathematically equivalent and numerically well-posed.

Although $f_3$ achieves the lowest RSS and highest $R^2$, it uses 4 parameters compared to 2 for $f_1$ and $f_2$. With only $n = 7$ data points, this leaves just 3 degrees of freedom, raising serious concerns about overfitting.

Comparing $f_1$ and $f_2$ directly --- both with 2 parameters and 5 degrees of freedom --- $f_2$ is superior on every criterion: lower RSS (0.00680 vs 0.00701), lower RMSE, lower AIC ($-22.695$ vs $-22.484$), and lower BIC ($-22.857$ vs $-22.646$). The AIC and BIC explicitly penalise model complexity, so their preference for $f_2$ over $f_1$ is meaningful.

\medskip
\noindent\textbf{Conclusion:} $f_2(x) = Axe^{-bx}$ is the best candidate. It achieves near-identical fit to $f_3$ with half the parameters, and outperforms $f_1$ on all information criteria.

\subsubsection*{(d)}
Overfitting occurs when a model captures noise rather than the underlying signal, fitting the training data closely but generalising poorly to new observations. The main ways to avoid it are:

\begin{itemize}
    \item \textbf{Information criteria (AIC, BIC):} These penalise the log-likelihood by a function of the number of parameters, rewarding parsimony. BIC applies a stronger penalty and is preferred when the true model is believed to be among the candidates.
    \item \textbf{Cross-validation:} Holding out part of the data to evaluate predictive performance on unseen points directly tests generalisation.
    \item \textbf{Physically motivated models:} Choosing functional forms that reflect the known behaviour of the system reduces the risk of spurious parameter proliferation.
    \item \textbf{Residual analysis:} A well-fitted model should show structureless, homoscedastic residuals with no systematic patterns.
\end{itemize}

\noindent\textbf{Assessment of the three models.} With $n = 7$ observations, a rule of thumb is to allow at most $\lfloor n/5 \rfloor = 1$ to $2$ free parameters for robust generalisation.

$f_1$ and $f_2$ each use 2 parameters, which is appropriate for this dataset size. $f_3$ uses 4 parameters, leaving only 3 residual degrees of freedom. The intercept of $f_3$ is not significant ($p = 0.154$), suggesting that at least one parameter is superfluous. The extrapolation result ($\hat{y}(4) = 1.107$) confirms that $f_3$ has more free parameters than needed and overfits the data.

\subsubsection*{(b) SVM analysis}

We have chosen to perform our analysis using Support Vector Machine.

Code is heavily commented but there are a few points worth discussing further. 

The dataset was split into training and test sets using an $80:20$ proportion. Since the amount of input data was limited - $150$ entries with $108$ \texttt{Good} labels and $42$ \texttt{Bad} labels, we decided to check the proportions of \texttt{Good} and \texttt{Bad} labels in the sampling split. With the random seed set to $42$ the split was as below:

\input{class_distribution.tex}

As it can be seen, the proportions of the original dataset are similar to the proportions in train and in test datasets, thus the split can be described as representative of the original dataset.

The standard SVM model was trained using a radial kernel. The target variable was converted to a factor before training, so the model performed classification rather than regression. The predictors were scaled, which is important for SVM because the method is sensitive to the relative scale of input variables.

\subsubsection*{(c) Results}

The SVM model was trained as follows:

\begin{verbatim}
model <- svm(
  x = data_train_x,
  y = data_train_y,
  kernel = "radial",
  scale = TRUE)
\end{verbatim}

This resulted in the following predictions:

\input{svm_confusion_matrix.tex}

As we can see, the model works but it performs barely better than a naive model predicting only \texttt{Good} label for all cases, having accuracy at $0.7333$ as compared to naive accuracy at $0.7$. This is probably caused by the small dataset size, the use of default SVM parameters and class imbalance, having most of the data labeled as \texttt{Good}. Since the problem is credit risk, we could sensibly assume that the more optimal would be a model that makes less mistakes in labeling \texttt{Bad} cases as \texttt{Good} even if it has an overall lower accuracy. A \texttt{Bad} case predicted as \texttt{Good} is the dangerous error in credit risk.

We can address this by using class weights that increase the penalty for false \texttt{Good} predictions.

\begin{verbatim}
class_weights <- c(
  Good = 1,
  Bad = sum(data_train_y == "Good") / sum(data_train_y == "Bad")
)

model_weighted <- svm(
  x = data_train_x,
  y = data_train_y,
  kernel = "radial",
  scale = TRUE,
  class.weights = class_weights
)
\end{verbatim}

The weighted model, evaluated on the same train/test split, performed as follows.

\input{svm_confusion_matrix_weighted.tex}

The resulting overall accuracy is lower, but the weighted model reduces the number of \texttt{Bad} cases incorrectly classified as \texttt{Good}. Depending on the preferred types of errors the weights can be further adjusted. Below are the final metrics of the predictions of both SVM models.

\input{svm_metrics.tex}
